# Agent Instructions

Follow these rules for all code changes.

## Comment Policy

Write self-explanatory code.

Do not add comments that describe what the code does. Improve names, types, functions, and structure instead.

Comments are allowed only when they explain non-obvious reasons or constraints. Use one of these prefixes:

- WHY:
- SECURITY:
- PERF:
- COMPAT:
- BUSINESS:

Before finishing any change, review the diff and remove comments that merely restate the code.

If a comment seems necessary, first try to make the code clearer so the comment is unnecessary.
